# 关键决策记录（摘要）

## ADR-001：本地优先，而非云端 MVP

- **背景**：个人使用；数据为医疗影像源文件。
- **决策**：默认本机 Web + 本地磁盘；不强制 Redis/S3/账号。
- **后果**：实现快、隐私好；多设备协同需后续加存储适配器。

## ADR-002：合并 = 多输出合成单文件

- **背景**：用户确认合并语义。
- **决策**：`merge=true` 时拼接为单个 mp4/gif，序列间黑场分隔；默认 `false` 按序列分文件（多文件则 zip）。
- **后果**：需 ffmpeg concat；医生单文件接收方便，但损失「按序列挑选」清晰度——默认不合并。

## ADR-003：引擎与 API 分离

- **背景**：已有 CLI 脚本；未来可能有 App/队列。
- **决策**：`engine` 无 Web 依赖；API/CLI 均为适配层。
- **后果**：可测性高；禁止在路由里写窗宽窗位逻辑。

## ADR-004：质量默认 high

- **背景**：目标消费端是接诊医生，不是家属随手预览。
- **决策**：默认 `quality=high`，并提供 low/medium 控制体积以便传输。
- **后果**：默认文件更大；UI 提示「发给医生建议高清，微信传输可改标准」。

## ADR-005：MVP 不做双前端 / 不做 App

- **背景**：原方案含 React + Flutter，成本高。
- **决策**：静态 Web 页 + FastAPI；App 留到验证真实压缩包之后。
- **后果**：移动端用浏览器访问本机或后续再包壳。

## ADR-006：进程内队列作为默认 Queue

- **背景**：单用户本机。
- **决策**：`InProcessQueue`；接口对齐未来 Celery。
- **后果**：进程重启任务丢失（可接受）；需文档说明。

## ADR-007：GIF 强制上限

- **背景**：全层 GIF 不可用。
- **决策**：按质量档限制边长与帧数；超限抽帧。
- **后果**：GIF 不保证每层都有；会诊优先推荐 MP4。
