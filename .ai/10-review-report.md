## 发现项（按严重度）

### Critical（上线前应处理）

| ID | 项 | 说明 | 建议 |
|----|----|------|------|
| C1 | 公网默认可无令牌 | `ACCESS_TOKEN` 为空时 API 对可达者开放，仅日志警告 | 生产 compose 强制要求 token；或 `public_mode` 下缺 token 拒绝启动 |
| C2 | 医疗数据公网暴露风险 | 上传包/输出在服务器磁盘，UUID 难猜但可被盗链/撞库+泄漏 | 强制 HTTPS；短时签名下载 URL；日志禁止文件名 PHI |
| C3 | 任务状态仅内存 | 进程重启后 job/upload 元数据丢失，磁盘孤儿依赖清理扫目录 | SQLite 持久化 job 表；或文档明确“重启丢失任务” |

### High

| ID | 项 | 说明 | 建议 |
|----|----|------|------|
| H1 | 限流单进程内存 | 多副本/多 worker 时限流不共享；可被绕过 | Redis 限流或反代层限流 |
| H2 | `trust_x_forwarded_for` 默认 true | 若无可信反代，客户端可伪造 IP 绕过限流 | 默认 false；仅在反代后开启 |
| H3 | 访问令牌在 sessionStorage | XSS 可窃取；无轮换/无过期 | 短期 HttpOnly Cookie + CSRF；或 token 轮换 |
| H4 | 预览/下载 blob 与对象生命周期 | 多次预览产生 blob URL，部分路径未统一 revoke | 统一 revoke 上一预览 blob |
| H5 | README 仍偏“本地优先/开发” | 与用户 UI 口径不一致；示例仍绑真实 rar 路径 | 对齐用户文案；示例用合成数据 |

### Medium

## 分模块 Review

### 引擎 (`engine/`)

- **强项**：发现/窗位/流式编码/合并 re-encode/RAR 工具链回退。
- **风险**：大序列 CPU/磁盘压力无背压；压缩传输语法依赖 pydicom 插件是否齐全；MONOCHROME1/rescale 已有，彩色/多帧边界未充分测。
- **建议**：对“仅原始轴位”增加可选过滤（Scout/Processed 可默认折叠）。

### API / 任务

- **强项**：uploads + jobs 分离、artifact 列表、preview 白名单。
- **风险**：InProcess 队列无持久化；`get_job_service` 单例 + 内存 map 无法水平扩展。
- **建议**：上 SQLite + 单 worker 即可显著改善公网重启体验。

### 安全

- **强项**：关 docs、扩展名、流式大小、headers、令牌 compare_digest。
- **缺口**：见 C1/C2/H1/H2；无审计日志（谁何时上传 Study）。
- **建议**：access log（脱敏）+ 失败登录计数锁定。

### 前端

- **强项**：用户向文案、明暗主题、双进度、格式匹配预览。
- **风险**：无 PWA/离线；大文件上传失败重试弱；鉴权弹层可访问性基本够用。
- **建议**：上传失败一键重试；显示剩余保留时间（bootstrap `job_ttl_hours`）。
