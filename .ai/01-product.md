# 产品定位与需求

## 1. 问题

医院导出的 CT/MRI 等多为 DICOM 源文件（常打成 zip/rar）。  
接诊医生（B/C/D 医院）往往没有 PACS/专业阅片软件，无法直接打开。  
需要把源文件转成**通用可播格式**（MP4 / GIF），用手机、电脑自带播放器即可看序列内容。

## 2. 典型流程

```
病人在 A 医院检查
    → 拿到光盘/网盘/压缩包（DICOM）
    → 用本工具本地上传/选择压缩包
    → 选择：格式、质量、是否合并为单文件
    → 得到 MP4 或 GIF（单文件或多文件 zip）
    → 通过微信/网盘/U 盘发给 B/C/D 医生
    → 医生用系统播放器直接查阅
```

## 3. 目标用户与非目标

| 角色 | 是否目标 | 说明 |
|------|----------|------|
| 操作者（病人侧或协助转换的人） | 是（当前唯一操作者） | 个人本地使用 |
| 接诊医生 B/C/D | 是（消费端） | 只收结果文件，不装本软件 |
| 放射科正式诊断阅片 | 否 | 不替代诊断工作站；无测量/标注/报告 |
| 多租户 SaaS 医院客户 | 否（未来扩展） | 架构预留，MVP 不做 |

## 4. 核心价值主张

- **可读**：医生零安装专业软件。
- **可传**：文件体积可控，方便微信/网盘传递。
- **可信**：窗宽窗位与序列顺序尽量忠实于源片；文件名带序列描述便于医生识别。
- **本地**：源文件默认不出本机，降低隐私风险。

## 5. 功能需求

### 5.1 必须（MVP）

| ID | 需求 | 说明 |
|----|------|------|
| F01 | 压缩包输入 | 支持 zip；尽力支持 rar/7z（依赖系统工具时降级提示） |
| F02 | DICOM 发现 | 递归扫描；`.dcm`/`.DCM`；无扩展名探测 |
| F03 | 按序列输出 | 默认按 `SeriesInstanceUID` 分组，每序列一个媒体文件 |
| F04 | 输出格式 | `mp4`、`gif` |
| F05 | 质量档位 | `low` / `medium` / `high`（医生会诊默认 `high`） |
| F06 | 合并开关 | `merge=false`：多文件打包 zip；`merge=true`：合并为**单个** mp4/gif |
| F07 | 排序 | `InstanceNumber`，回退 `ImagePositionPatient[Z]` |
| F08 | 窗宽窗位 | DICOM tag → 文件名 `W{ww}L{wc}` → 自动归一化 |
| F09 | 进度与结果 | 任务状态、失败原因、本地下载路径 |
| F10 | 本地清理 | 可配置保留时长，默认任务完成后可手动清或 24h 策略 |

### 5.2 明确不做（MVP）

- 账号体系 / 多用户权限
- 公网上传与对象存储（接口预留）
- 跨序列「智能」猜测合并规则（合并时用明确策略，见 5.3）
- PACS / DICOMweb
- AI 自动窗位、测量、标注、报告
- 正式医疗器械认证路径

### 5.3 「合并」精确定义（已确认）

**合并 = 将本次任务产生的多个输出媒体，合并成单个文件。**

| `merge` | 行为 |
|---------|------|
| `false`（默认） | 每序列一个文件；若 >1 个则额外打成 `result.zip` 便于一次带走 |
| `true` | 按序列顺序拼接为**一个** `merged.mp4` 或 `merged.gif`；序列之间插入短黑场 + 可选字幕/文件名条（便于医生区分段落） |

合并排序规则（确定性）：

1. 同一 Study 内：按 `SeriesNumber`，再 `SeriesDescription`
2. 跨 Study：按 StudyDate/StudyTime，再 StudyInstanceUID
3. 序列内帧：InstanceNumber / IPP-Z（与单序列一致）

> 注意：合并后的单文件**不能**当作精确诊断切片序列；仅便于医生「一条视频看完所有相关序列」。默认仍推荐不合并、按序列分文件。

## 6. 质量与体积（面向医生传阅）

| 档位 | 用途 | MP4 | GIF |
|------|------|-----|-----|
| low | 快速预览/弱网 | 长边约 50%，较高压缩，fps 5–8 | 长边 ≤256，抽帧 |
| medium | 日常传阅 | 长边 ≤1024 或原分辨率取小，平衡体积 | 长边 ≤480 |
| high（默认） | 给医生会诊 | 原分辨率优先，较低压缩，fps 10–12 | 长边 ≤640；体积警告 |

GIF 始终施加硬上限（帧数/尺寸），避免不可用的超大文件。  
「超清/无损」不做独立档位；需要时可后续加 `ultra`。

## 7. 成功标准（个人使用）

1. 真实医院 zip 包可解压并找出序列。
2. 输出 MP4 可在 macOS/Windows/手机直接播放。
3. 序列顺序与窗位观感可被医生接受（相对源片无严重颠倒/全黑全白）。
4. 合并单文件时，医生能分辨「不同序列段落」。
5. 整机本地完成，无需外网。

## 8. 非功能

| 项 | 目标 |
|----|------|
| 隐私 | 默认本地；日志不落 PatientName 明文（可配置） |
| 性能 | 单序列流式写盘，避免全帧进内存 |
| 可扩展 | Storage / Queue / Auth 可替换，见架构文档 |
| 可运维 | 单命令启动 Web；CLI 仍可直接调引擎 |
